### Part 2 사용 방법

1. 전체 지도에서 곡의 점이나 장르 라벨을 선택해 대장르로 확대합니다. 오른쪽 위 도구막대의 **장르 버튼**에서도 이동할 수 있습니다.
2. 대장르 안의 항성이나 **장르 버튼**으로 연 패널에서 세부장르를 선택합니다.
3. 세부장르 항성계에 도착하면 중심 항성과 세 곡의 궤도가 나타납니다. 세로 메뉴 대신 오른쪽에 플레이리스트와 리퀴드 글래스 추천 카드를 함께 담은 패널이 자동으로 표시됩니다. 플레이리스트 또는 궤도 라벨로 곡을 선택할 수 있습니다.
4. 전체 지도·대장르에서는 왼쪽 드래그로 3차원 공간을 회전하고, 오른쪽 드래그·두 손가락으로 이동합니다. 휠/트랙패드는 오른쪽 아래 +·− 버튼과 같은 방식으로 카메라가 접근·후퇴합니다. 지도에 포커스를 두면 방향키로 회전, +/−로 접근·후퇴, 0으로 초기화할 수 있습니다. 항성계에서는 좌우 드래그·방향키로 같은 대장르의 세부장르를 탐색하며, 접근·후퇴도 가능합니다. 미니맵 테두리는 카메라 시야를 XY 평면에 투영한 범위입니다.
5. 전체 지도와 대장르에서는 오른쪽 위 **추천 버튼**으로 추천 카드를 열고 닫습니다. 세부장르 항성계에서는 플레이리스트와 함께 오른쪽 패널 아래에 고정 표시됩니다. 카드 위 **조합 편집 아이콘**에서 장르×악기 조합을 추가·삭제하고 비중을 조절합니다. 추천 목적지를 선택하면 해당 세부장르 항성계로 이동합니다.
6. 오른쪽 아래 **⌖ 버튼**으로 연 미니맵에서 현재 위치·방문 기록·이동 경로를 확인하고 다른 장르로 이동합니다. 제목 옆 뒤로가기 버튼이나 로고 옆 경로로 상위 단계에 돌아갑니다.

대장르 방문은 **다른 장르 또는 전체 지도에서 해당 장르에 실제 도착했을 때** 1회 기록됩니다. 추천으로 세부장르에 바로 도착해도 부모 장르 방문을 기록합니다. 같은 장르 안의 세부장르 이동과 부모 화면 복귀는 대장르 방문을 중복 계산하지 않습니다. 세부장르 방문과 이동 경로는 별도로 유지합니다. 곡 선택, 호버, 취소된 이동은 방문을 늘리지 않습니다.

오른쪽 위 세로 도구막대의 **방문 기록 버튼**에서 전체 방문 수, 방문한 장르 수, 장르별 횟수와 색·밝기 누적을 확인합니다. 각 장르의 별은 방문당 색이 20%씩 쌓여 5회에 호버와 같은 장르색이 되며, 밝기는 방문당 12%씩 높아져 10회에 최대 2.2배가 됩니다. 별 크기는 누적에 따라 커지지 않습니다. 방문 횟수 자체는 상한 없이 기록됩니다. 발표와 탐색 사이를 오가면 상태가 유지되며, 새로고침하면 이번 탐색 기록은 초기화됩니다.

전체 지도·대장르의 장르·추천·방문 기록·미니맵 패널은 오른쪽 위 도구막대 옆에 한 번에 하나씩 표시합니다. 세부장르 항성계에서는 세로 메뉴를 숨기고 오른쪽 고정 패널의 위에 플레이리스트, 아래에 추천 카드를 표시하며 지도는 그 왼쪽 영역을 사용합니다. 전체 지도·대장르의 초기 화면에서는 모두 접혀 있습니다. 세부장르 항성계의 추천 카드는 미니맵을 열어도 오른쪽 고정 패널 안에 유지됩니다. 패널은 지도 위에 겹쳐 표시되므로 열고 닫아도 카메라 배율이나 표시 영역이 바뀌지 않습니다. 모든 장르와 곡은 Canvas 밖의 실제 버튼으로도 선택할 수 있습니다. WebGL을 사용할 수 없으면 목록 탐색으로 전환합니다. 시스템의 모션 감소 설정에서는 카메라 이동을 짧게 하고 입자 수와 UI 애니메이션을 줄입니다.

상단은 작은 브랜드·사운드·메뉴 버튼만 표시합니다. 햄버거 메뉴의 목차에서 표지·각 슬라이드·탐색 화면으로 이동합니다. 로고를 누르면 전체 별 지도가 있는 시스템 홈으로 돌아갑니다. 소리 아이콘을 누르면 저음·노이즈·느린 필터 변화를 Web Audio로 직접 합성한 우주 앰비언트가 켜집니다. 외부 녹음이나 음원 파일을 사용하지 않습니다. 처음에는 꺼져 있고, 끄거나 탭을 숨기면 부드럽게 음량을 낮춘 뒤 오디오 처리를 중단합니다.

탐색 화면의 장식용 캡션·하단 문구·미니맵 범례·조작 안내는 표시하지 않습니다. 햄버거 메뉴의 **사용법**과 **지도·추천 설명**에서 확인할 수 있습니다. 플레이리스트와 추천을 담은 오른쪽 패널은 세부장르 항성계 진입 시 나타납니다. 제목 주변에는 작은 장르·세부장르 이름과 뒤로가기 버튼만 표시합니다. 로고 옆 경로는 대장르부터 시작하며, 별도 캡션·설명·곡 수 통계는 표시하지 않습니다.

### 데이터와 구형 음악 지도

원본은 루트의 `mtg_jamendo_genre_instrument.csv`이며 수정하거나 이동하지 않습니다.

| 항목 | 개수 / 처리 |
| --- | --- |
| 고유 곡 | 4,961곡, ID의 앞자리 0 보존 |
| 대장르 | 15개, `/`가 포함된 이름도 하나의 장르 |
| 세부장르 | `\|`로 분리한 146개 |
| 악기 | `\|`로 분리한 125개, 지도 관계와 추천에 사용 |
| t-SNE 입력 | 중복을 제거한 2,382개 장르·세부장르·악기 태그 조합 |

`frontend/scripts/prepare_data.py`가 장르·세부장르·악기 태그를 각각 L2 정규화하고 cosine 유사도 기여도를 15%·30%·55%로 설정합니다. 태그가 많다고 해당 묶음의 비중이 커지지 않으며, 서로 다른 장르도 같은 악기를 가지면 관계가 생깁니다. 이 특징으로 3차원 t-SNE(perplexity 40, seed 42, PCA 초기화, 1,000회 최적화)를 계산합니다.

곡 ID로 고정한 작은 오프셋으로 같은 조합의 곡을 분리한 다음, 세 축의 분산을 균형 있게 조정하고, 고정된 192개 방향의 투영 분포를 구 내부 분포에 맞춰 빈 공간을 완화한 뒤 반경 순위를 구의 부피에 맞게 펼칩니다. 반경 12인 구 내부를 채우는 표시용 배치이며, 모든 점을 구 표면에 붙이지 않습니다. 장르·세부장르의 기준점은 소속 곡의 XYZ 평균입니다. 미니맵은 같은 좌표의 XY 투영을 사용합니다.

생성 결과는 `frontend/public/data/music-catalog.json`에 포함됩니다. **가까운 별은 태그 관계를 탐색하기 위한 단서이고, 별 사이 거리·방향·깊이는 실제 음향 유사도의 측정값이 아닙니다.** 구형 변환은 원래 임베딩의 거리도 바꿉니다. 실제 음원 분석은 사용하지 않습니다. 여러 세부장르를 가진 곡은 해당 그룹마다 나타나므로 그룹별 곡 수의 합이 전체 곡 수보다 클 수 있습니다.

별은 `refer/index (1).html`의 작은 점·시드별 느린 알파 변화·부드러운 가장자리 감쇠 방식을 사용합니다. 큰 원이나 십자 광채를 사용하지 않습니다. 포인터 주변의 실제 곡을 광선으로 조회하고 거리·깊이로 가중한 장르 투표로 클러스터를 선택합니다. 선택된 장르에 속한 곡만 해당 장르색으로 부드럽게 활성화되며, 다른 곡의 밝기는 유지됩니다. 홈의 장르 이름과 연결 안내선은 해당 클러스터의 호버·키보드 포커스 시에만 표시됩니다. 가까이 배치되고 태그가 유사한 실제 곡 쌍 최대 40개만 옅은 연결선으로 표시합니다. 이 선은 실제 음원 분석 결과가 아니며, 배경에서 짧게 움직이는 꼬리별은 장식입니다. 별·라벨·카메라·미니맵은 동일한 좌표를 사용하고 탐색 단계가 바뀌어도 좌표를 다시 계산하지 않습니다.

### 우주 인터랙션과 후속 아이디어

참고: `refer/index (1).html`. 첫 발표 표지의 구형 별 무리는 실제 곡 ID마다 하나의 별을 배치한 도입 연출입니다. 구 위의 위치·표면을 흐르는 빛·배경 별똥별은 음악적 거리, 추천 관계, 재생 데이터가 아닙니다. 탐색 화면은 악기를 포함한 태그 관계로 만든 구형 지도 좌표를 사용합니다.

전체 지도 홈에서는 구 전체가 약 4분 30초에 한 바퀴씩 천천히 회전하며, 장르를 가리키거나 키보드로 선택하는 동안에는 회전을 멈춥니다. 모션 감소 설정에서는 자동 회전과 반짝임을 끕니다. 홈의 별 지도와 배경은 마우스 움직임을 따라가지 않습니다. 표지와 장르·항성계의 배경은 마우스를 따라 깊이별로 움직이고, 장르·항성계의 탐색 카메라는 위치를 유지한 채 시선을 부드럽게 돌립니다. 드래그·줌·버튼 조작 중에는 시선 연출을 가라앉힙니다. 발표 전환은 기존 내용을 먼저 숨긴 뒤 같은 별 공간 안에서 전진·후퇴하고 다음 내용을 드러냅니다. 지도→장르→항성계 이동은 화각을 45도로 유지하며 실제 카메라가 곡선 경로로 이동하고, 도착한 뒤 항성계·라벨·제목을 드러냅니다. 이동 중 다시 목적지를 선택하면 현재 카메라 위치에서 새 경로로 이어집니다. 도착 후에만 방문을 기록하며 모션 감소 설정에서는 별똥별·시선 추적·속도 연출을 끄고 비행을 짧게 처리합니다.

후속 아이디어(현재 미구현): 참고 HTML처럼 클릭 후 1인칭 시점에서 행성 표면이 화면 아래에 깔리는 진입 장면. 현재 지도→대장르→세부장르 탐색에서 어느 단계의 장소인지, 뒤로가기·미니맵·곡 선택과 어떻게 연결할지 먼저 정한 뒤 적용합니다. 음악 데이터로 지형·행성 특성이 측정된 것처럼 보이지 않게 구분해야 합니다.

데이터를 다시 생성할 때만 Python **3.11–3.13**과 과학 계산 패키지가 필요합니다.

```sh
cd frontend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r scripts/requirements.txt
npm run data:prepare
npm run data:test
npm run data:check
```

`data:check`는 Python 표준 라이브러리만 사용하며 곡 수, 고유 ID, 3차원 좌표와 구의 경계, 그룹 중심·연결선, 원본 SHA-256을 검증합니다. `data:test`는 악기 변경에 따른 유사도 변화, 특징 묶음의 정규화, 구 내부 분포의 결정성을 확인합니다. 원본 데이터를 교체하는 경우 전처리 스크립트의 예상 개수 검증도 함께 갱신하세요.

### 추천과 음악 시각화의 범위

추천은 브라우저 안에서 계산하는 **태그 일치 데모**입니다. 초기 조합은 Jazz×Piano 50, Pop×Piano 30, Rock×Guitar 20입니다. 비중을 전체 합으로 나눈 뒤, 후보 세부장르와 대장르가 같은 조합에 대해 다음 값을 합산합니다.

```text
score(세부장르) = Σ (조합의 정규화 비중 × 그 세부장르에서 해당 악기를 포함하는 곡의 비율)
```

점수가 양수인 후보를 내림차순으로 정렬하고 동점은 이름순으로 정렬합니다. 대장르마다 가장 높은 후보 하나만 남겨 최대 3개의 서로 다른 장르를 제안합니다. 각 장르는 해당 색상의 먼지를 담은 독립된 유리 버튼으로 한 패널 안에 가로로 표시하며, 선택하면 추천 세부장르로 이동합니다. 모든 비중이 0이거나 조합이 없으면 안내를 표시합니다. 실제 사용자 취향 학습, 추천 서버, 로그인, 스트리밍은 포함하지 않습니다.

입자·구름·곡 썸네일은 코드로 생성합니다. 음악 막대는 곡 ID로 만든 무음 시각화 신호입니다. CSV의 상대 MP3 경로는 메타데이터로만 보존하며 재생 URL로 사용하지 않습니다. 실제 음원·앨범 커버·오디오 분석 결과로 표시하지 않습니다.

### 협업 및 연결 지점

| 위치 | 역할 |
| --- | --- |
| `frontend/src/presentation/chapters/` | Part 1의 독립된 6개 챕터. 각 파일의 `body`와 `visualization`에 JSX를 넣으면 됩니다. |
| `frontend/src/presentation/ChapterFrame.tsx` | 발표의 공통 제목·본문·시각화 슬롯 |
| `frontend/src/domain/catalog.ts` | CSV에서 파생된 곡·장르 모델 및 조회 함수 |
| `frontend/src/domain/recommendations.ts` | 추천 입력·결과 타입과 데모 점수 함수 |
| `frontend/src/state/reducer.ts` | 탐색 단계·도착·방문 기록·조합 상태 |
| `frontend/src/scene/` | 구형 음악 지도, 카메라, 화면 라벨, 항성계 및 입자 |
| `frontend/src/components/` | 플레이리스트·추천 유리병·미니맵·목록 탐색 |
| `frontend/src/domain/visualization.ts` | `VisualizationSignal` 및 곡별 데모 신호 |

예를 들어 챕터의 `body={undefined}`를 `body={<p>발표 내용</p>}`로 바꾸고, `visualization`에 팀원이 만든 차트 컴포넌트를 넣을 수 있습니다. 챕터 제목과 순서는 `Presentation.tsx`의 registry에서 관리합니다.

실제 추천 API는 `PreferencePair[]`를 요청하고 `RecommendationTarget[]`로 응답을 매핑하는 경계에 연결합니다. `RecommendationJar`의 현재 동기 계산 호출부를 로딩·오류 상태가 있는 비동기 요청으로 바꾸면 됩니다. 지도에 없는 목적지는 이 경계에서 걸러야 합니다.

실제 음원은 `Track.id`를 기준으로 재생 가능한 URL을 가져오는 플레이어를 추가하고, Web Audio `AnalyserNode`의 데이터를 `VisualizationSignal.levels`로 전달하도록 연결할 수 있습니다. 그때 음원 권한·URL·오디오 상태를 별도로 다루면 됩니다. 앰비언트 소리를 켰을 때만 합성용 `AudioContext`를 생성합니다. 이 배경음은 선택한 실제 곡의 재생 및 막대 시각화와 별개입니다.


핵심 테스트는 실제 카탈로그 연결, 추천 비율 계산과 비중 변경, 조합 중복 방지, 비중 0, 도착 중복·취소·재방문, 세부장르 순환, 데모 신호의 결정성을 확인합니다.

브라우저 확인 시에는 발표 6개 챕터, 지도→장르→항성계, 곡 3개 선택, 드래그·버튼·키보드 전환, MIX 편집, 미니맵, 모션 감소, WebGL 대체 화면을 확인합니다. 주요 데스크톱 크기는 1280×720, 1440×900, 1920×1080입니다.

구현 검증에서 타입 검사, 핵심 테스트 7개, 데이터 검사와 프로덕션 빌드를 통과했습니다. 별도 Chrome 테스트 환경에서 위 세 해상도와 390×844의 패널 접기, 실제 별 클릭, 빠른 이동·재방문, 추천 편집, 키보드 포커스 순환, 새로고침 초기화, WebGL 미지원·컨텍스트 손실 복구를 확인했으며 콘솔·페이지 오류는 없었습니다.

추가 변경 검증에서는 48px 상단 메뉴, 전체/장르 지도 드래그·휠 줌·배율 초기화, 드래그와 별 클릭 구분, 항성계 넘기기 유지를 확인했습니다. 합성 앰비언트는 버튼 클릭 전 AudioContext 미생성, 클릭 후 실제 출력 신호, 끄기·탭 숨김 시 중단 및 복귀 시 재개를 Chrome에서 확인했습니다.

Three.js를 포함한 3D 장면은 Part 2 진입 시 불러오는 별도 청크입니다. 현재 약 989KB(gzip 약 277KB)여서 Vite의 500KB 청크 크기 안내가 발생합니다. 발표 화면에서는 이 청크를 요청하지 않는 것을 확인했습니다.
