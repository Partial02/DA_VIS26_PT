### Part 2 사용 방법

0. **무대 편성부터 시작합니다(장르 아틀라스 방식).** 탐색 화면을 열면 왼쪽에 무대 패널이 펼쳐집니다. 벤치는 스타일 패밀리 5행 × 세션 9열의 표이며, 실제로 존재하는 22칸에 연주자 성운이 놓여 있습니다. 성운을 누르거나 무대로 끌어다 놓으면 무대에서 성운들이 하나로 섞이고, 그 편성으로 연주할 수 있는 세부장르 순위가 바로 아래에 뜹니다. 순위에서 세부장르를 고르면 편성이 자동 조정되고 해당 세부장르로 이동합니다. 도구막대의 **무대 버튼**으로 패널을 접고 펼칩니다.
1. 장르 이름으로 직접 찾아갈 수도 있습니다. 전체 지도에서 곡의 점이나 장르 라벨을 선택해 대장르로 확대합니다. 오른쪽 위 도구막대의 **장르 버튼**에서도 이동할 수 있습니다.
2. 대장르 안에서는 별이 연한 장르색으로 보입니다. 세부장르 이름이나 실제 소속 별을 호버하면 해당 영역만 진한 장르색과 광채로 강조됩니다. 별 주변·이름 또는 **장르 버튼**으로 연 목록에서 세부장르를 선택합니다.
3. 세부장르로 진입하면 같은 별 지도의 해당 곡 영역으로 줌인합니다. 곡 좌표와 별 개수는 유지하고, 별도 항성계 장면으로 교체하지 않습니다. 오른쪽 플레이리스트·추천 패널은 세부장르 진입 시에만 자동 표시되며, 해당 영역의 곡 목록을 **무대 편성에 어울리는 순**(장르 아틀라스 곡 정렬)으로 보여줍니다. 곡을 누르면 Jamendo에서 해당 CC 라이선스 음원을 재생합니다. 도착 후에는 무대의 성운들이 합쳐진 성운이 항성계 뒤에 깔리고, 플레이리스트 상위 세 곡과 곡 이름이 그 안에서 천천히 궤도를 돕니다. 다른 곡을 플레이리스트에서 선택하면 그 곡도 궤도에 표시됩니다. 배경 지도와 오른쪽 패널은 유지하며, 공전은 표시용 연출입니다.
4. 전체 지도·대장르·세부장르 항성계에서는 왼쪽 드래그로 3차원 공간을 회전하고, 오른쪽 드래그·두 손가락으로 이동합니다. 휠/트랙패드는 오른쪽 아래 +·− 버튼과 같은 방식으로 카메라가 접근·후퇴합니다. 지도에 포커스를 두면 방향키로 회전, +/−로 접근·후퇴, 0으로 초기화할 수 있습니다. 미니맵 테두리는 카메라 시야를 XY 평면에 투영한 범위입니다.
5. 전체 지도·대장르에서는 오른쪽 위 **추천 버튼**으로 추천 카드를 열고 닫습니다. 세부장르에서는 플레이리스트 아래에 추천 카드가 고정 표시됩니다. 카드 위 **무대 편성 아이콘**(세부장르에서는 다이얼로그, 그 외에는 왼쪽 무대 패널)에서 22명의 연주자(세션 9종 × 스타일 패밀리 5종) 중 원하는 조합을 무대에 올리고, 세부장르 전체 추천 순위를 확인합니다. 카드에는 서로 다른 장르의 상위 세부장르 3개가 표시됩니다. 추천 목적지를 선택하면 무대 편성이 자동 조정(핵심 세션 등판·쓰이지 않는 연주자 퇴장)되고 해당 세부장르 항성계로 이동합니다.
6. 오른쪽 아래 **⌖ 버튼**으로 연 미니맵에서 현재 위치·방문 기록·이동 경로를 확인하고 다른 장르로 이동합니다. 제목 옆 뒤로가기 버튼이나 로고 옆 경로로 상위 단계에 돌아갑니다.

대장르 방문은 **다른 장르 또는 전체 지도에서 해당 장르에 실제 도착했을 때** 1회 기록됩니다. 추천으로 세부장르에 바로 도착해도 부모 장르 방문을 기록합니다. 같은 장르 안의 세부장르 이동과 부모 화면 복귀는 대장르 방문을 중복 계산하지 않습니다. 세부장르 방문과 이동 경로는 별도로 유지합니다. 곡 선택, 호버, 취소된 이동은 방문을 늘리지 않습니다.

오른쪽 위 세로 도구막대의 **방문 기록 버튼**에서 전체 장르·세부장르 중 방문한 영역의 탐색률과 방문 기록을 확인합니다. 방문한 항목만 표시하며, 장르별 큰 막대는 전체 장르 방문 중 비중을 보여줍니다. 각 장르 아래의 세부장르 막대는 그 장르 안에서 기록된 세부장르 탐색 횟수를 기준으로 비중을 표시합니다. 각 장르의 별은 방문당 색이 20%씩 쌓여 5회에 호버와 같은 장르색이 되며, 밝기는 방문당 12%씩 높아져 10회에 최대 2.2배가 됩니다. 별 크기는 누적에 따라 커지지 않습니다. 방문 횟수 자체는 상한 없이 기록됩니다. 발표와 탐색 사이를 오가면 상태가 유지되며, 새로고침하면 이번 탐색 기록은 초기화됩니다.

전체 지도에서는 왼쪽 무대 패널을 펼친 채 시작하고, 오른쪽 도구 패널은 접어 둡니다. 대장르는 별 지도를 넓게 사용하고, 세부장르에 들어가면 오른쪽에 기본 너비 300px의 플레이리스트·추천 패널이 화면 끝에 붙어 표시됩니다. 장르로 돌아오면 고정 패널을 숨기고 지도 영역을 복원합니다. 대장르의 장르·방문 기록 버튼은 맨 오른쪽 세로 도구막대에 남아 있습니다. 장르·방문 기록·미니맵 도구 패널은 별 지도 위에 겹쳐 표시하므로 열고 닫아도 지도 영역이 바뀌지 않습니다. 세부장르에서는 세로 도구막대를 숨기며, 뒤로가기·경로·미니맵·추천으로 다른 영역을 탐색합니다. 모든 장르와 세부장르의 곡은 Canvas 밖의 버튼으로도 선택할 수 있습니다. WebGL을 사용할 수 없으면 목록 탐색으로 전환합니다. 모션 감소 설정에서는 카메라 이동을 짧게 하고 반짝임과 UI 애니메이션을 끕니다.

상단은 작은 브랜드·사운드·메뉴 버튼만 표시합니다. 햄버거 메뉴의 목차에서 표지·각 슬라이드·탐색 화면으로 이동합니다. 로고를 누르면 전체 별 지도가 있는 시스템 홈으로 돌아갑니다. 소리 아이콘을 누르면 저음·노이즈·느린 필터 변화를 Web Audio로 직접 합성한 우주 앰비언트가 켜집니다. 외부 녹음이나 음원 파일을 사용하지 않습니다. 처음에는 꺼져 있고, 끄거나 탭을 숨기면 부드럽게 음량을 낮춘 뒤 오디오 처리를 중단합니다.

탐색 화면의 장식용 캡션·하단 문구·미니맵 범례·조작 안내는 표시하지 않습니다. 햄버거 메뉴의 **사용법**과 **지도·추천 설명**에서 확인할 수 있습니다. 플레이리스트와 추천을 담은 오른쪽 고정 패널은 세부장르 진입 시 나타납니다. 제목 주변에는 작은 장르·세부장르 이름과 뒤로가기 버튼만 표시합니다. 로고 옆 경로는 대장르부터 시작하며, 별도 캡션·설명·곡 수 통계는 표시하지 않습니다.

### 데이터와 t-SNE 요약

원본은 루트의 `mtg_jamendo_genre_instrument.csv`이며 수정하거나 이동하지 않습니다.

| 항목 | 개수 / 처리 |
| --- | --- |
| 고유 곡 | 4,961곡, ID의 앞자리 0 보존 |
| 대장르 | 15개, `/`가 포함된 이름도 하나의 장르 |
| 세부장르 | `\|`로 분리한 146개 |
| 악기 | `\|`로 분리한 125개, 지도 관계와 추천에 사용 |
| t-SNE 입력 | 중복을 제거한 2,382개 장르·세부장르·악기 조합 × 286차원 특징 |

- **특징 구성:** 대장르·세부장르·악기 묶음을 각각 정규화. 입력 cosine 유사도에 장르 15%·세부장르 30%·악기 55%를 반영합니다.
- **임베딩:** scikit-learn 1.7.2의 3차원 t-SNE. cosine 거리, perplexity 40, 직접 계산한 PCA 초기 좌표, seed 42, 최대 1,000회 반복을 사용합니다.
- **구형 표시:** 곡 ID 기반 오프셋으로 각 곡을 분리한 뒤 축·밀도·반경을 조정해 반경 12인 구 내부에 배치합니다.
- **실행 방식:** Python에서 미리 생성한 `frontend/public/data/music-catalog.json`과 장르 아틀라스 추천 모델 `frontend/public/data/atlas-model.json`을 브라우저가 읽습니다. 호버·추천·방문으로 좌표를 재계산하지 않습니다.
- **해석 범위:** 태그 관계를 탐색하기 위한 지도입니다. 구형 후처리는 t-SNE의 거리도 바꾸므로 화면 간격을 실제 음향 차이로 해석하지 않습니다.

정확한 정규화 식, 전체 파라미터, 구형 후처리, 선·호버·추천·방문 규칙은 **[로직 상세 문서](docs/logic.md)**에서 확인할 수 있습니다.

데이터를 다시 생성할 때만 Python **3.11–3.13**과 과학 계산 패키지가 필요합니다.

```sh
cd frontend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r scripts/requirements.txt
npm run data:prepare
npm run data:test
npm run data:check
```

`data:check`는 Python 표준 라이브러리만 사용하며 곡 수, 고유 ID, 3차원 좌표와 구의 경계, 그룹 중심·연결선, 원본 SHA-256을 검증합니다. `data:test`는 악기 변경에 따른 유사도 변화, 특징 묶음의 정규화, 구 내부 분포의 결정성을 확인합니다. 원본 데이터를 교체하는 경우 전처리 스크립트의 예상 개수 검증도 함께 갱신하세요.

### 우주 인터랙션

- **발표 표지:** 실제 곡 ID마다 하나의 별을 배치한 구형 도입 연출. 표지 위치와 표면의 빛 흐름은 음악적 거리나 추천 관계를 나타내지 않습니다.
- **탐색 홈:** 태그로 만든 구형 지도가 약 4분 30초에 한 바퀴 회전. 호버·키보드 포커스 중에는 회전을 멈춥니다.
- **별빛·장르색:** 작은 별의 밝기를 천천히 변화시키고, 실제 곡의 장르에 맞춰 호버 색과 방문 누적 색을 적용합니다. 장르 이름은 호버·키보드 포커스 시에만 보입니다.
- **선:** 고정된 가는 선은 태그가 유사한 일부 곡 쌍, 이름 옆 선은 라벨 위치 안내, 움직이는 꼬리별은 장식입니다.
- **발표 이동:** 기존 내용을 숨긴 뒤 같은 별 공간 안에서 전진·후퇴하고 다음 내용을 표시합니다.
- **지도 이동:** 화각 45도와 실제 별 좌표를 유지합니다. 장르→세부장르는 현재 시선 방향을 유지한 채 해당 영역으로 줌인하고, 같은 장르로 복귀하면 줌아웃합니다. 별 지도는 이동 내내 유지됩니다. 이동 중 새 목적지를 선택하면 현재 카메라 위치에서 이어집니다.
- **시점·모션 감소:** 전체 지도·장르·항성계의 카메라와 배경은 포인터 위치를 따라가지 않습니다. 모든 단계에서 드래그로 회전·이동하고 휠로 접근·후퇴합니다. 모션 감소 설정에서는 자동 회전·반짝임을 끄고 이동을 짧게 처리합니다.

### 추천과 음악 시각화의 범위

추천은 **장르 아틀라스(Genre Atlas v4) 추천 알고리즘**을 브라우저에서 그대로 계산합니다. 장르 이름 대신 **악기 편성**을 질의로 삼습니다. 악기 125종을 9개 세션(드럼·퍼커션·베이스·기타·건반·신스·현악·관악·보컬)으로 묶고, 장르 15개를 악기 출현율로 군집화한 5개 스타일 패밀리(밴드·전자·오케스트라·어쿠스틱·그루브)와 교차해 22명의 연주자를 만듭니다. 처음 무대는 비어 있으며, 연주자를 올리면 146개 세부장르 전체에 점수를 매깁니다.

```text
score(S) = min(1, [0.86 × core(S) + 0.14 × size(S)] × fam(S) × explore(S))
core(S)  = λ × F1(무대 세션, w_S) + (1 − λ) × F1(무대 세션, w_상위장르),  λ = n_S / (n_S + 12)
size(S)  = log(n_S + 1) / log(n_max + 1)
fam(S)   = 0.55 + 0.45 × (무대에서 상위 장르의 패밀리에 속한 연주자 비율)
explore  = 1.06 (상위 장르를 아직 방문하지 않음) / 1.00
```

카드에는 서로 다른 장르의 최고 세부장르 3개를, 무대 편성 다이얼로그에는 점수가 양수인 전체 순위를 8개씩 페이지로 표시합니다. 탐험 보너스는 Part 2의 대장르 방문 기록(`genreVisits`)을 사용합니다. 세부장르 안의 곡은 점수를 표시하지 않고 **편성 적합도 + 길이 보정 + 해시 미세 난수** 순으로 정렬한 뒤, 아티스트마다 첫 곡을 먼저 세웁니다. 정확한 식은 [로직 상세 문서](docs/logic.md#8-추천항성계음악-막대)에 있습니다. 실제 사용자 취향 학습, 추천 서버, 로그인은 포함하지 않습니다.

곡을 선택하면 Jamendo API(JSONP)로 `TRACK_ID`의 CC 라이선스 음원 주소를 받아 재생하고, 실패하면 `TRACK_ID` 기반 저장소 주소로 한 번 더 시도합니다. 기본 `client_id`가 들어 있으며, 플레이어의 **API 키** 버튼에서 개인 `client_id`로 바꿀 수 있습니다(브라우저 `localStorage`에 저장). 세부장르를 벗어나면 재생을 멈춥니다. CSV의 상대 MP3 경로는 사용하지 않습니다.

입자·구름·곡 썸네일은 코드로 생성합니다. 음악 막대는 곡 ID로 만든 무음 시각화 신호이며 실제 음원 분석 결과가 아닙니다. 앨범 커버는 표시하지 않습니다.

### 검증

```sh
cd frontend
npm run typecheck
npm test
npm run data:check
npm run build
```

핵심 테스트는 실제 카탈로그 연결, 장르 아틀라스 모델과 카탈로그의 일치, 설계서 예시(오케스트라 건반 1명 → Neoclassical·Waltz·Opera·Orchestral, 전자 드럼+베이스 → Drum and Bass·Industrial·Dance·Techno) 재현, 축소 추정·탐험 보너스, 편성 자동 조정, 곡 정렬과 아티스트 분산, 무대 상태, 도착 중복·취소·재방문, 세부장르 순환, 데모 신호의 결정성을 확인합니다.

브라우저 확인 시에는 발표 6개 챕터, 지도→장르→항성계, 곡 3개 선택, 드래그·버튼·키보드 전환, 무대 편성·추천 순위, Jamendo 재생, 미니맵, 모션 감소, WebGL 대체 화면을 확인합니다. 주요 데스크톱 크기는 1280×720, 1440×900, 1920×1080입니다.

장르 아틀라스 통합 후 검증(Node 22.23.5)에서 타입 검사, 프런트엔드 테스트 28개, 데이터 검사와 프로덕션 빌드를 통과했습니다. 그 이전 검증에서는 프런트엔드 테스트 23개와 전처리 테스트 3개를 통과했습니다. 별도 Chrome 테스트 환경에서 위 세 해상도와 390×844의 패널 접기, 실제 별 클릭, 빠른 이동·재방문, 추천 편집, 키보드 포커스 순환, 새로고침 초기화, WebGL 미지원·컨텍스트 손실 복구를 확인했으며 콘솔·페이지 오류는 없었습니다.

추가 변경 검증에서는 48px 상단 메뉴, 전체/장르 지도 드래그·휠 줌·배율 초기화, 드래그와 별 클릭 구분, 항성계 탐색을 확인했습니다. 합성 앰비언트는 버튼 클릭 전 AudioContext 미생성, 클릭 후 실제 출력 신호, 끄기·탭 숨김 시 중단 및 복귀 시 재개를 Chrome에서 확인했습니다.

Three.js를 포함한 3D 장면은 Part 2 진입 시 불러오는 별도 청크입니다. 현재 Vite의 500KB 청크 크기 안내가 발생하며, 정확한 크기는 빌드 로그에서 확인할 수 있습니다. 발표 화면에서는 이 청크를 요청하지 않는 것을 확인했습니다.
