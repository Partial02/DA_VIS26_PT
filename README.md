# DA_VIS26
박현우 교수님 데이터분석과시각화(M3239.003100) 4조

## INNER//VERSE

음악 장르의 우주를 탐색하는 데스크톱 중심 웹 프로토타입입니다. Part 1은 팀원이 내용을 채울 발표 챕터 6개, Part 2는 실제 MTG-Jamendo CSV를 사용하는 인터랙티브 지도입니다.

### 실행

Node.js **22.18 이상**이 필요합니다. 정적 데이터가 포함되어 있어 웹 실행에 Python이나 백엔드가 필요하지 않습니다.

```sh
cd frontend
npm ci
npm run dev
```

터미널에 출력된 주소를 열어주세요. 기본 주소는 `http://127.0.0.1:5173`입니다.

- 발표: `/#/story/1`부터 `/#/story/6`
- 탐색 바로가기: `/#/explore`
- 프로덕션 빌드: `npm run build`
- 빌드 확인: `npm run preview`

Vite의 상대 경로 빌드와 해시 내비게이션을 사용하므로 정적 호스팅에서도 별도 라우트 재작성 없이 사용할 수 있습니다. 폰트는 Google Fonts를 사용하고, 연결되지 않으면 시스템 폰트로 표시합니다.

### Part 2 사용 방법

1. 전체 지도에서 곡의 점이나 장르 라벨을 선택해 대장르로 확대합니다. **모든 장르 살펴보기** 목록에서도 이동할 수 있습니다.
2. 대장르 안의 항성이나 **세부장르 목록**에서 세부장르를 선택합니다.
3. 항성계에 도착하면 중심 항성과 세 곡의 궤도가 나타납니다. 우측 상단 카드 또는 궤도 라벨로 곡을 선택할 수 있습니다.
4. 지도 위에서 좌우로 드래그하거나 이전/다음 버튼으로 같은 대장르 안의 세부장르를 이름순으로 탐색합니다. 지도를 클릭해 포커스를 준 뒤 좌우 방향키로도 전환할 수 있습니다.
5. 우측 하단 **MIX**에서 장르×악기 조합을 추가·삭제하고 비중을 조절합니다. 추천 목적지를 선택하면 해당 세부장르 항성계로 이동합니다.
6. 좌측 하단 미니맵에서 현재 위치·방문 기록·이동 경로를 확인하고 다른 장르로 이동합니다. 상단 경로로 이전 단계에 돌아갑니다.

방문은 **세부장르 항성계에 실제 도착했을 때** 1회 기록됩니다. 곡 선택, 호버, 취소된 이동은 방문을 늘리지 않습니다. 재방문하면 밝기가 누적되고 상한에서 멈춥니다. 발표와 탐색 사이를 오가면 상태가 유지되며, 새로고침하면 초기화됩니다.

좁은 화면에서는 `THREE SIGNALS`와 `NEXT WORLD` 버튼으로 패널을 펼칩니다. 모든 장르와 곡은 Canvas 밖의 실제 버튼으로도 선택할 수 있습니다. WebGL을 사용할 수 없으면 목록 탐색으로 전환합니다. 시스템의 모션 감소 설정에서는 카메라 이동을 짧게 하고 입자 수와 UI 애니메이션을 줄입니다.

### 데이터와 t-SNE

원본은 루트의 `mtg_jamendo_genre_instrument.csv`이며 수정하거나 이동하지 않습니다.

| 항목 | 개수 / 처리 |
| --- | --- |
| 고유 곡 | 4,961곡, ID의 앞자리 0 보존 |
| 대장르 | 15개, `/`가 포함된 이름도 하나의 장르 |
| 세부장르 | `\|`로 분리한 146개 |
| 악기 | `\|`로 분리한 125개, 추천 패널에만 사용 |
| t-SNE 입력 | 중복을 제거한 339개 장르·세부장르 태그 조합 |

`frontend/scripts/prepare_data.py`가 장르 one-hot(가중치 2)과 세부장르 multi-hot(가중치 1)으로 실제 t-SNE를 계산합니다. 2차원, cosine 거리, perplexity 30, seed 42, random 초기화, 1,000회 최적화를 사용합니다. 결과는 비율을 보존하며 균일하게 스케일링하고, 같은 조합의 곡들을 대표 좌표 주변 반경 0.32 안에 ID 기반의 결정적인 오프셋으로 펼칩니다.

생성 결과는 `frontend/public/data/music-catalog.json`에 포함됩니다. 악기·음향 특징은 좌표 계산에 사용하지 않습니다. 가까운 점은 입력한 장르 태그의 구조를 나타내며, **장르 사이의 거리나 떨어진 성단의 배치는 실제 음악적 유사성을 뜻하지 않습니다.** 여러 세부장르를 가진 곡은 해당 그룹마다 나타나므로 그룹별 곡 수의 합이 전체 곡 수보다 클 수 있습니다.

데이터를 다시 생성할 때만 Python **3.11–3.13**과 과학 계산 패키지가 필요합니다.

```sh
cd frontend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r scripts/requirements.txt
npm run data:prepare
npm run data:check
```

`data:check`는 Python 표준 라이브러리만 사용하며 곡 수, 고유 ID, 좌표, 그룹 연결, 원본 SHA-256을 검증합니다. 원본 데이터를 교체하는 경우 전처리 스크립트의 예상 개수 검증도 함께 갱신하세요.

### 추천과 음악 시각화의 범위

추천은 브라우저 안에서 계산하는 **태그 일치 데모**입니다. 초기 조합은 Jazz×Piano 50, Pop×Piano 30, Rock×Guitar 20입니다. 비중을 전체 합으로 나눈 뒤, 후보 세부장르와 대장르가 같은 조합에 대해 다음 값을 합산합니다.

```text
score(세부장르) = Σ (조합의 정규화 비중 × 그 세부장르에서 해당 악기를 포함하는 곡의 비율)
```

점수가 양수인 후보를 내림차순으로 3개 제안하고 동점은 이름순으로 정렬합니다. 모든 비중이 0이거나 조합이 없으면 안내를 표시합니다. 실제 사용자 취향 학습, 추천 서버, 로그인, 스트리밍은 포함하지 않습니다.

입자·구름·곡 썸네일은 코드로 생성합니다. 음악 막대는 곡 ID로 만든 무음 시각화 신호입니다. CSV의 상대 MP3 경로는 메타데이터로만 보존하며 재생 URL로 사용하지 않습니다. 실제 음원·앨범 커버·오디오 분석 결과로 표시하지 않습니다.

### 협업 및 연결 지점

| 위치 | 역할 |
| --- | --- |
| `frontend/src/presentation/chapters/` | Part 1의 독립된 6개 챕터. 각 파일의 `body`와 `visualization`에 JSX를 넣으면 됩니다. |
| `frontend/src/presentation/ChapterFrame.tsx` | 발표의 공통 제목·본문·시각화 슬롯 |
| `frontend/src/domain/catalog.ts` | CSV에서 파생된 곡·장르 모델 및 조회 함수 |
| `frontend/src/domain/recommendations.ts` | 추천 입력·결과 타입과 데모 점수 함수 |
| `frontend/src/state/reducer.ts` | 탐색 단계·도착·방문 기록·조합 상태 |
| `frontend/src/scene/` | t-SNE 점, 카메라, 화면 라벨, 항성계 및 입자 |
| `frontend/src/components/` | 플레이리스트·추천 유리병·미니맵·목록 탐색 |
| `frontend/src/domain/visualization.ts` | `VisualizationSignal` 및 곡별 데모 신호 |

예를 들어 챕터의 `body={undefined}`를 `body={<p>발표 내용</p>}`로 바꾸고, `visualization`에 팀원이 만든 차트 컴포넌트를 넣을 수 있습니다. 챕터 제목과 순서는 `Presentation.tsx`의 registry에서 관리합니다.

실제 추천 API는 `PreferencePair[]`를 요청하고 `RecommendationTarget[]`로 응답을 매핑하는 경계에 연결합니다. `RecommendationJar`의 현재 동기 계산 호출부를 로딩·오류 상태가 있는 비동기 요청으로 바꾸면 됩니다. 지도에 없는 목적지는 이 경계에서 걸러야 합니다.

실제 음원은 `Track.id`를 기준으로 재생 가능한 URL을 가져오는 플레이어를 추가하고, Web Audio `AnalyserNode`의 데이터를 `VisualizationSignal.levels`로 전달하도록 연결할 수 있습니다. 그때 음원 권한·URL·오디오 상태를 별도로 다루면 됩니다. 현재 앱은 `AudioContext`를 생성하지 않습니다.

### 검증

```sh
cd frontend
npm run typecheck
npm test
npm run data:check
npm run build
```

핵심 테스트는 실제 카탈로그 연결, 추천 비율 계산과 비중 변경, 조합 중복 방지, 비중 0, 도착 중복·취소·재방문, 세부장르 순환, 데모 신호의 결정성을 확인합니다.

브라우저 확인 시에는 발표 6개 챕터, 지도→장르→항성계, 곡 3개 선택, 드래그·버튼·키보드 전환, MIX 편집, 미니맵, 모션 감소, WebGL 대체 화면을 확인합니다. 주요 데스크톱 크기는 1280×720, 1440×900, 1920×1080입니다.

구현 검증에서 타입 검사, 핵심 테스트 7개, 데이터 검사와 프로덕션 빌드를 통과했습니다. 별도 Chrome 테스트 환경에서 위 세 해상도와 390×844의 패널 접기, 실제 별 클릭, 빠른 이동·재방문, 추천 편집, 키보드 포커스 순환, 새로고침 초기화, WebGL 미지원·컨텍스트 손실 복구를 확인했으며 콘솔·페이지 오류는 없었습니다.

Three.js를 포함한 3D 장면은 Part 2 진입 시 불러오는 별도 청크입니다. 현재 약 986KB(gzip 약 276KB)여서 Vite의 500KB 청크 크기 안내가 발생합니다. 발표 화면에서는 이 청크를 요청하지 않는 것을 확인했습니다.

디자인은 `refer/index (1).html`, `refer/inner-verse.md`, liquid glass 이미지를 참고했습니다. 참고 파일은 런타임 의존성이 아닙니다. [The Pudding의 장르 이야기](https://pudding.cool/2023/10/genre/)와 [Love Songs](https://pudding.cool/2024/11/love-songs/)는 발표 경험의 참고 자료이며, 해당 콘텐츠는 발표 슬롯에 작성하지 않았습니다.
